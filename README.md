# TG API Client

Multi-user Telegram client built with Telethon, FastAPI, React, and PostgreSQL.

## Architecture

```text
Frontend (React) -> Traefik -> Backend (FastAPI) -> PostgreSQL
                         |              |
                         v              v
                    MCP Server     Worker (sync)
```

The Docker stack contains six services:

- `backend` - FastAPI REST API with JWT and API key authentication.
- `worker` - background Telegram synchronization and command execution.
- `web` - React dashboard served by nginx.
- `mcp` - MCP SSE server for AI agent integration.
- `postgres` - PostgreSQL 16 database.
- `traefik` - reverse proxy for the web app, API, and MCP endpoint.

## Quick Start

1. Copy the example environment file:

   ```bash
   cp .env.example .env
   ```

2. Edit `.env` and set at least:

   - `POSTGRES_PASSWORD`
   - `JWT_SECRET_KEY`
   - `SESSION_ENCRYPTION_KEY`
   - `ADMIN_EMAIL`
   - `ADMIN_PASSWORD`
   - `TELEGRAM_API_ID`
   - `TELEGRAM_API_HASH`

   `DATABASE_URL` is generated by Docker Compose from `POSTGRES_*` by default. Override it only when using an external database or a password that needs URL encoding.

3. Start the stack:

   ```bash
   docker compose up --build
   ```

4. Open the app at [http://localhost:8080](http://localhost:8080).

The initial admin account is created from `ADMIN_EMAIL` and `ADMIN_PASSWORD` when the backend starts and no admin user exists yet.

## Security Notes

- Do not commit `.env`. It can contain Telegram API credentials, database passwords, JWT secrets, and session encryption keys.
- Replace every `change-me` placeholder before running outside local development.
- Replace the example `SESSION_ENCRYPTION_KEY` before any shared or production deployment.
- Keep `SESSION_ENCRYPTION_KEY` stable after accounts are connected. Changing it makes previously stored Telegram sessions impossible to decrypt.
- New user accounts are inactive by default and must be enabled by an admin.

Generate useful secrets:

```bash
openssl rand -hex 32
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

## Features

- Multi-user registration and login with JWT.
- Multiple Telegram accounts per user.
- Telegram phone code login with optional 2FA password.
- Chat list, cached message reading, and message sending.
- Channel join and leave commands.
- REST API with JWT and API key authentication.
- MCP SSE endpoint for agent integrations.
- Admin panel for user/account management and audit logs.
- Encrypted Telegram session storage.

## API Authentication

Authenticated API routes accept either:

- `Authorization: Bearer <token>` from `/api/auth/login`.
- `X-API-Key: tgc_...` created in the dashboard.

## MCP Integration

Connect your MCP client to:

```text
http://localhost:8080/mcp/sse
```

Send the API key as `X-API-Key: tgc_...` when your MCP client supports custom headers. For clients that cannot send SSE headers, `?api_key=YOUR_API_KEY` is still accepted for compatibility; the server stores it in the SSE session and does not echo it back in the MCP message endpoint URL.

Available tools:

- `list_telegram_accounts`
- `list_chats`
- `get_recent_messages`
- `send_telegram_message`
- `search_messages`
- `subscribe_to_channel`

## Development

Backend dependencies are in `backend/requirements.txt`; frontend dependencies are in `web/package.json`.

Useful commands:

```bash
docker compose up --build
docker compose logs -f backend
docker compose logs -f worker
```
